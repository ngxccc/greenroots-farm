# Database & Migration Standards

## 1. Schema

- Columns are `snake_case`; TypeScript properties are `camelCase`.
- Primary keys are UUIDv7 from `primaryKeyUuid`. Every base entity carries timezone-aware `created_at` and `updated_at`.
- Money is integer VND in the columns defined under `apps/api/src/database/schemas` (`basePrice`, `shippingFee`, `totalAmount`, `amount`, `unitPrice`); DTOs and JSONB contracts add the `Vnd` suffix. Never use `numeric`, `float`, or `double`.
- Enums are PostgreSQL enum types generated by `pgEnum` from `@greenroots/shared` values (`order_status`, `payment_method`, `delivery_day`). Never add a value the shared enum lacks.
- Index every foreign key and choose `ON DELETE` explicitly.
- Soft delete only where history matters: add `deleted_at timestamptz` and filter it in every query.

## 2. Indexes

| Type           | Use                                             | Example                                             |
| :------------- | :---------------------------------------------- | :-------------------------------------------------- |
| B-tree         | Equality and range lookups                      | `users.email`, `orders.user_id`                     |
| Composite      | Multi-column filters, highest cardinality first | `(order_id, created_at)`                            |
| Partial        | Sparse states                                   | `ON batches (status) WHERE status = 'in_stock'`     |
| Unique partial | One active row per scope                        | one active subscription per `(user_id, product_id)` |
| GiST exclusion | Non-overlapping ranges                          | delivery windows, plot allocation                   |
| GIN            | JSONB containment                               | `jsonb_contracts` lookups                           |

- Every index answers a real query; no speculative indexes.
- Verify a hot-path query change with `EXPLAIN (ANALYZE, BUFFERS)` before shipping.

## 3. Queries

Project the columns you need instead of `SELECT *` in a hot path:

```ts
const rows = await db
  .select({ id: products.id, name: products.name, status: products.status })
  .from(products)
  .where(eq(products.status, "active"));
```

- Paginate large, changing lists by keyset (`created_at`, `id`) instead of deep `OFFSET`.

## 4. Transactions

- Combine interdependent mutations in one `db.transaction(async (tx) => { ... })`. Checkout locks batch rows, verifies and decrements stock, creates the order, line items, and payment intent as one unit.
- Keep transactions short: no HTTP calls, email, uploads, or heavy hashing inside them.
- Default to `READ COMMITTED`; use row locks or constraints for correctness and raise isolation only with a measured reason.
- Recompute totals, discounts, and shipping fees from persisted data; never trust client totals.

## 5. Migrations (expand & contract)

1. **Expand** — add nullable columns or new tables; deploy code that writes both shapes.
2. **Backfill** — populate existing rows in batched background work.
3. **Contract** — deploy code that reads only the new shape, then drop the old column in a later release.

Renaming `products.price` to `products.base_price`: release A adds `base_price` and writes both while backfilling; release B reads `base_price` and stops writing `price`; release C drops `price`.

- Migrations are forward-only. A destructive change needs an ADR.
- Never hold a long lock on a large table; create indexes `CONCURRENTLY` where supported.

## 6. Integrity

- `CHECK` constraints: `available_quantity >= 0` and `initial_quantity >= 0` on batches; `base_price >= 0` on products; `shipping_fee >= 0`, `subtotal >= 0`, `discount_amount >= 0`, and `total_amount >= 0` on orders; `quantity > 0` and `unit_price >= 0` on order line items.
- `payments` requires `order_id IS NOT NULL OR subscription_id IS NOT NULL`.
- Declare these with Drizzle `check()` in the schema; the generated migration applies them and the snapshot stays authoritative.
- Validate order status transitions in the domain service and cover them with integration tests.
- All timestamps are `timestamptz`; never store local time.

## 7. Seeding

- Three tiers in dependency order: reference types, catalog, then operational rows.
- `--clean` truncates every application table and reseeds; truncation refuses to run when `NODE_ENV=production`.
- Dates are relative to the run date, so demo batches and subscriptions never expire on a fixed day.
- Seeding is idempotent: stable seed ids plus `onConflictDoNothing()`.
- Demo credentials are local fixtures, never production secrets.

## 8. Session Cleanup

`TokenCleanupService` runs on bootstrap and every 24 hours, executing `DELETE FROM refresh_tokens WHERE expires_at < NOW()` outside the request path. Cleanup is maintenance, not part of the rotation invariant in ADR-0015.
